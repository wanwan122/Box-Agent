# Mac-CUA — Box-Agent 直接 Driver 接口

本技能复用已有 Mac-CUA 的观察、输入与原生窗口操作约定，适配 Box-Agent 直接 MCP 接口。这里的 `get_app`、`get_state`、`press_key`、`type_text`、`set_value` 分别对应 REPL 版的 `cua.getApp`、`App.getAXState`、`App.pressKey`、`App.typeText`、`App.setValue`。当前环境没有 `cua_repl` 时，不调用 REPL 工具，也不把 JavaScript 示例当作 MCP 参数。

先使用 `ensure_cua_ready` 准备托管连接，再通过 `tool_search` 发现当前提供的 App MCP 工具。以 `get_app` 绑定应用，后续工具沿用同一 app 引用；使用最近一次观察的元素编号，不传原生 Driver 的 token、snapshot 或 session 参数。适配器管理自己的 Driver session，不管理宿主 daemon。无需 mac-cua。用户要求通过 GUI 完成时，不用脚本、Office API 或直接写文件替代操作。

## 观察与操作

- `get_state` 返回当前交互窗口的 AX tree；需要确认文档正文或布局时加 `screenshot=true`。
- 元素 ID 只属于最近一次观察。操作、菜单切换或窗口变化后重新观察，再选择 ID。动作返回成功不等于界面完成；`unverifiable`、超时或过期后先观察，不自动重放输入。
- 对具有原生操作或可选择状态的元素，优先操作 AX 元素。文档正文缺少 AX 文本时，根据截图和应用快捷键编辑。

## 注意观察图片

每次收到截图，都认真阅读其中与任务有关的实际内容，再决定下一步。注意文字、段落边界、数值、选中状态和布局是否符合要求；不要把预期结果当成画面事实，也不要仅凭此前操作、工具成功或字数正常推断内容正确。发现可见错误时及时处理，看不清的内容不要猜测。

利用操作过程中已经获得的图片完成观察，无需固定格式汇报或逐行抄录。不要为了最终核验额外要求重新打开窗口、重新打开文件或补拍截图。

## 原生打开/保存窗口

弹窗可能是独立窗口，AX tree 中不一定存在主文档到弹窗的父子关系。继续使用应用引用观察当前交互窗口；以返回的窗口和元素为准，不猜测旧窗口或旧元素 ID。若弹窗未被返回，使用 `list_windows` 和观察结果诊断，不把主窗口中的同名按钮当成弹窗按钮。

文件浏览器的列视图中，文件名可能是 `AXList` 下的 `AXTextField`。显示 `open` 等 action 不保证执行后真的选中或打开。此时：

1. 用 AX 操作“视图选项”菜单，选择“列表”，然后重新观察。
2. 找到文件名所属的整行（`AXRow`），对行做单击。不要点文件名子文本框，也不要用双击代替选择。没有 `AXPress` 的可选择行仍可由 Driver 通过 `AXSelected` 选中。
3. 重新观察，确认目标行被选中，且“打开”按钮启用，再操作该按钮。
4. 重新观察，确认文件弹窗消失，文档标题和内容与目标文件一致。

这里的关键是列视图与列表视图暴露的 AX 结构不同，不是文件夹或文件本身不可操作。不要把列视图中的 AX 失败立即转成坐标点击；先采用上述 AX 列表路径。若用户要求 AX-only，不能用坐标操作绕过失败。

原生打开、保存和前往文件夹弹窗中，沿用 Mac-CUA 的输入约定：焦点进入字段并选中原值后，使用 `paste` 输入文件名或路径，不使用 `set_value`。保存时使用观察到的文件名/位置字段与菜单。每次编辑字段后核对实际值；路径输入或快捷键是否生效由下一次观察确认。只有保存弹窗关闭且文档标题等界面证据一致，才能报告保存完成。

Word for Mac 另存为时，优先采用已验证成功的目录导航方法：打开保存弹窗后，先按 `cmd+shift+g`，观察“前往文件夹”输入界面，用 `paste` 输入目标目录路径，再按 Return。根据随后返回的界面确认已进入目标目录，再选中文件名字段、粘贴目标文件名，重新观察后操作“保存”按钮。不要先反复点击列视图中的文件夹名称；仅看到末级文件夹同名（例如输入和输出目录都叫 W01）不能确认位置正确，应核对其父目录。若快捷键后出现“未找到结果”等其他界面，先检查当前焦点，不把它当成已完成目录切换。

## Office 文档保真

修改已有文档前先从截图读取原文。只修改任务指定内容，保留其余段落和顺序，不能凭记忆全选重写。

- 替换标题或段落文字时，只选中文字，保留末尾的段落结束符。不要假定 `Shift+End` 或“选中整行”只包含文字；选区可能跨过段落边界。从已确认的光标位置选择准确范围，并在替换前核对选区。
- 观察修改后的图片时，注意新标题与下一条正文是否仍分别成段，下一段开头有没有丢失、合并或重复。AX tree 不含正文时，不能用 AX 返回正常推断正文正确。
- 追加内容时确认光标位于正文末尾，用段落换行新增独立段落，不用软换行代替。完成后核对追加内容只出现一次，且原有段落文字、边界和顺序均保持。
- Word for Mac 的 `cmd+down` / `cmd+up` 是按段移动，不是文档末尾／开头。使用 `press_key(key="cmd+end")` 到文档末尾、`cmd+home` 到开头；不要把其他 macOS 应用的导航快捷键套用到 Word。若追加位置错误，修复时先纠正定位方法，不重复同一导航操作。
- 若发现段落合并或其他误改，先检查当前状态，再通过 GUI 撤销对应编辑或修复明确的段落边界；重新核对后再保存，不通过全选重写掩盖问题。
- 根据过程中实际观察到的内容报告结果；文件名变化、字数正常或保存弹窗关闭，不代表正文一定正确。

按用户要求决定保存顺序；要求保留输入且最后另存为时，不提前保存覆盖输入文件。
